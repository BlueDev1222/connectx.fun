# ConnectX

A Minecraft community social network running on **GitHub Pages + Supabase**. Your computer is not part of production hosting.

## Hosting

- GitHub Pages serves the static Vite/React/TypeScript frontend at https://connectx.fun.
- Supabase hosts authentication, Postgres/RLS, private Storage, Realtime, and authenticated Edge Functions.
- The connected project URL and publishable key are already included in src/lib/public-config.ts. They are public credentials, not server secrets.
- The connectx-api Edge Function is deployed to the existing Supabase project. Its privileged key stays in Supabase's managed environment.
- Every push to main runs the GitHub Actions Pages workflow. No Vercel, paid third host, or running PC is required.

GitHub repository Settings → Pages → Source must be **GitHub Actions**, with custom domain **connectx.fun**. The workflow builds dist and publishes it. Do not serve raw source files from the repository root.

## Supabase Auth configuration

Set Authentication → URL Configuration:

- Site URL: https://connectx.fun
- Allowed redirect URL: https://connectx.fun/**

Email confirmation returns to /?flow=confirmation and password recovery to /?flow=recovery. The frontend exchanges PKCE codes through Supabase Auth and routes the player to the correct view. Configure SMTP, email confirmation, a 12-character minimum password, and leaked-password protection before a public launch.

## Database and owner

The six SQL migrations in supabase/migrations are already applied to project onvmeffhmruzshqlwakx.supabase.co. Do not rerun them against that project. The original tables and Auth accounts remain intact; cx_ tables isolate ConnectX data. No owner was inferred or created automatically.

Follow [docs/ADMIN.md](docs/ADMIN.md) to assign the first owner using a verified Auth UUID and a trusted SQL connection. Client-side route guards improve the UI; Postgres RLS and checked RPCs are the real authorization boundary. All staff commands remain server-authorized.

## Features

Profiles, Minecraft identity fields, posts/media/polls, replies, quotes, likes/reposts, private bookmarks, follows and approvals, communities and scoped moderation, server discovery, search/hashtags, realtime notifications and private messages, settings/privacy, reports, staff verification, audit records, support tickets, account export and deletion, legal templates, and dark/light themes.

Pages-compatible links use hashes, for example https://connectx.fun/#/home and https://connectx.fun/#/community/builders. Refreshing or sharing these URLs works without a server. Dynamic per-profile social preview metadata is not generated by this static hosting setup.

## Hosted backend

Source: supabase/functions/connectx-api. Endpoints provide media upload, account export, confirmed deletion, optional Minecraft lookup, and a public connectivity status. Protected endpoints validate the bearer token with Supabase Auth and require an active database profile before using server credentials. Unauthenticated access tests return 401; unauthorized origins return 403. Function gateway JWT validation is disabled only because the function implements explicit getUser(token) validation for every protected route.

Read [deployment](docs/DEPLOYMENT.md), [security](docs/SECURITY.md), and [Minecraft adapter](docs/MINECRAFT.md) for operational details and remaining integration boundaries. Legal pages remain review-required templates; actual Minecraft ownership verification, server player monitoring, and group messages are not enabled.
